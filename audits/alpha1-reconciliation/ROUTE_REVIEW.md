# Route review boundaries

The generated AST inventory enumerates101 route files,74 observed files and147
exported methods at the audited source. It resolves source imports through
application/infrastructure guards; this is a trace index, not an authorization
certificate. Current HTTP acceptance probes every non-public method and adds
the ten-role diagnostic/catalog/support matrix and connected request lifecycle.

## Reviewed guard families

- Ticket actions resolve getTicketRouteContext before domain use, then
  withTicketMutation takes the SHARED lifecycle barrier, fresh current identity,
  ticket visibility/lock and action authorization before keyed replay. Requester
  save/submit use lockDraftActor/lockRequesterTicket. Current application use cases
  enforce assigned-field actors, role/Area scope and atomic ticket_events/outbox.
- Tenancy administration uses independent current project grants or current
  Central/Tenant capability; EXCLUSIVE writers revalidate after the barrier and
  before idempotency. Survey staffing/workforce retain current operational role,
  explicit team/Area/obligation/snapshot checks. Graph placement grants no authority.
- Help Desk application scopes tenant/project/requester reads, hides another
  member's records, requires administrator status decisions and records messages
  plus administrative evidence in the held transaction. Catalog roles are exactly
  Requester/Viewer aliases; current Tenant Admin owns catalog mutations.
- Diagnostic GET rechecks administrator scope under a SHARED transaction. Its
  UUID/state/actor disclosure is now the explicitly approved Decision55 exception.
- Attachment handlers authorize the parent before parsing/bytes, then reread
  current authority after waiting on the lifecycle and request locks. Storage
  digests and attachment.downloaded evidence accompany ordinary authenticated reads.
- Public login/reset/register use their own invitation/password/rate-limit
  boundaries. Public invitation reads and health are intentional. POST /tenants
  is an inert404; retired legacy Area/subarea writes are inert409 adapters.
- observeProjectRoute establishes only a verified observation context; it does
  not replace the original handler's authorization. The recorder's separate
  transaction revalidates current identity/capability before telemetry persistence.

Existing actual PostgreSQL suites supply scoped/revoked/stale/replay/concurrency
and fault rollback witnesses for these shared families. The HTTP probe accepts
400 at validation-before-auth boundaries and409 only for explicit retired writes;
it never treats those probes as proof of every authenticated branch. Historical
receipt assertions are not relabelled as newly executed.
