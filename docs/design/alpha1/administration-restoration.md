# Administration Workflow Restoration

This owner-requested correction supersedes the in-page navigation and paired Tenant Accounts/reviews layout described in [the original administration increment](administration.md). Use the [Alpha 1 design hub](README.md) to carry this correction with continuing hardening work into Alpha 2.

Tenant Accounts, Central IT Reviews and Project Templates have separate route-backed pages under `/accounts`. Project Administration separates Personnel, Project Admins, Companies, Settings, Request Policy, Access and Recovery, and Diagnostics. Shared layouts retain each editor across sibling tab navigation; only the current page's area is visible. Internal page links expose current-page state. Account and review containers use the available padded content width.

The member wizard supports creating an employee or adding an existing eligible account. New employees supply a name, company email and initial password, then an associated project company, fixed operational role and optional explicit independent Project Admin grant. A final review states the exact access scope. Central IT starts the same workflow from Tenant Accounts after choosing a project; scoped Project Admin starts it inside that project. Company registration is visible on Companies. Central IT has a guided template editor for the established name, crew build, Area levels and discipline groups; project creation links to it.

Operational role labels use readable title case in a native scrollable list. The existing Axiom/Roboto identity, persistent sidebar, heading help, contained records, tenant/project/company isolation, archived restrictions and independent administrative/operational grants remain authoritative.

This increment crosses presentation, Identity account creation, Tenancy membership/grant coordination and Audit evidence because the user explicitly requested functioning account provisioning. The new authenticated project-scoped employee endpoint runs under the existing exclusive tenant barrier, revalidates current authority before idempotent replay, requires an associated same-tenant company, and commits account, membership, optional grant and evidence together. Public invite registration remains separate. Passwords are hashed and excluded from responses and administrative evidence. Shared template creation accepts an idempotency key for exact retries while retaining compatibility with existing clients.

The new rollback-owned PostgreSQL employee suite passed creation, independent grants, replay, duplicate/foreign scope and ineligible company refusal, Central IT without operational membership, audit failure rollback and retained request history.
