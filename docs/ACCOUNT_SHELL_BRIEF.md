# Account shell refinement

Mode: Operate. Owner's annotated browser comments request an authenticated name greeting beside Axiom and a right-side account navigation column that pushes the working page inward. This is a precisely specified, code-first extension of the existing shell, not a new identity.

## Direction contract

THESIS: Personal wayfinding without covering the desktop working surface or dismissing navigation when the user returns to work.

OWN-WORLD: Inherit the supplied Axiom artwork, Roboto, white surfaces, slate text, steel-blue structure and existing keyboard focus. No new tokens or raster assets.

STORY: The current authenticated account is greeted by name; Menu reveals the familiar account destinations. Links retain project context and Sign out retains per-browser-session revocation.

FIRST VIEWPORT: Existing sticky header carries Axiom, Hello plus the account's full name, and Menu at right. Open navigation fills a 280px right column below the header and narrows the main content at widths of 768px and above. Smaller screens use a modal right drawer with a close control, Escape dismissal and protected focus rather than crushing the workspace.

FORM: Precisely specified incumbent extension; no concept seed. Signature interaction is a persistent desktop working column versus a native mobile dialog. Long names wrap; account loading/failure never invents an identity, and failure exposes retry. No ornamental motion.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

Boundaries: no new permissions, account API, invitations, role changes or session policy. Report/print exports are a separate, lower-priority backlog item; a future meeting report must cover the authorized filtered population, not silently just the visible page, and disclose provenance. No bulk export is claimed by this refinement.
